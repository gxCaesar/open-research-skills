`review-others-manuscripts` 用于你作为受邀审稿人处理**别人的**投稿。一份审稿意见为编辑
回答一个问题：每条主张是否被为它提供的证据撑住；如果没有，什么才能撑住。其余内容都为
这个问题服务。

稿件是保密的、属于作者的。这个约束先约束你**能对它做什么**，然后才约束你写什么。

本地 [SKILL.md](../skills/review-others-manuscripts/SKILL.md) 是运行入口。

## 安装与首次调用

```bash
SKILL_DIR="$PWD/skills/review-others-manuscripts"
```

```text
使用 $review-others-manuscripts，initial-review 模式。稿件 PDF 在本地。
先按 confidentiality 判断我能不能用现在这套工具读它。
```

## 保密边界

**打开稿件之前先读这一节**，因为它有一部分约束的正是「打开」这个动作本身。

把保密稿件贴进外部服务，等于把它传输给了那个服务；除非该期刊的现行政策**点名**允许
该服务，否则按再分发处理。各出版社政策不同且在变化，读**这一家这一年**的政策，
不要套用你记得的另一家。

委托别人（或别的系统）读其中一部分，保密义务随文本一起转移；期刊政策决定这种委托
是否被允许。存在利益冲突就回避 —— 冲突是关于处境的，不是关于你的意图的。

## 从主张读到证据

按主张而不是按文档顺序读。线性通读产出的是关于**呈现**的意见，因为呈现是线性阅读最先
遇到的东西。

列出摘要与结论里的每条主张，定位为它提供的具体图 / 表 / 统计量，记录「主张」与
「该证据实际确立的东西」之间的差。**没有对应证据的主张**和**不支撑任何主张的证据**
都是发现；后者在返修稿里常见，通常意味着一条主张被撤了但它的装置没被删。

再问「即使方法本身没问题，报告的这个数还能怎么错」：split 从哪来、信息能不能跨过去；
独立单元是什么、报告的不确定性用的是不是它；指标在正文里有没有定义、定义与同名的标准
定义是否一致；对比方法有没有拿到可比的预算、是真跑的还是引用的。

## 严重度标定

| 严重度 | 判据 |
|---|---|
| Fatal | 改正之后结论活不下来 |
| Major | 结论大概能活，但在展示出来之前无法判断 |
| Minor | 主张不受影响，但呈现会误导 |
| Taste | 你会换个做法，而论文并不因此更差 |

Taste 级只配放在最后一小段，或者不放。**把 taste 级当 major 提，是一份意见变得对编辑
无用的最常见方式。**

每条请求必须是作者拿现有材料就能执行的。「再做一个更大的研究」不是请求；
「报出表 2 那个聚合数背后的逐中心分解」是。

## 返修轮

先读**改动**，再读回复信。回复信是关于改动的论证，改动本身在标记稿里。先读信会先给出
一个解释，之后标记稿看起来就会在印证它。

逐条对齐四列：你原来要求什么、信里声称改了什么、稿子现在写的是什么、这条是否解决。
常见的缺口：只在信里答了而稿子里没有（论文读者永远看不到那封信）；改掉了你指出的那句
但它支撑的主张在别处原样保留；为回应而新加的分析自带新缺陷（返修中的新材料按第一轮
标准读，不是更宽）；结论被削弱了而标题和摘要没跟着改。

**按是否解决来判，不按投入多少来判。**

## 校验审稿意见的形态

```bash
python3 "$SKILL_DIR/scripts/check_referee_report.py" \
  "$SKILL_DIR/examples/referee-report/clean.json"
```

已知坏的那份演示它挡什么 —— taste 级被提到 major、编辑面与作者面推荐不一致、
预审去回答了本该由审稿人回答的问题:

```bash
python3 "$SKILL_DIR/scripts/check_referee_report.py" \
  "$SKILL_DIR/examples/referee-report/known-bad.json"
```

它检查的是**形态**,不判断某条意见对不对。

## 交付与验收

编辑要在靠前位置拿到推荐意见和它所依据的两三条；作者要拿到每条都定位到位、可执行的
意见。写成两者都被满足的一份，不要出现与公开部分相矛盾的私下部分。

本 skill 里的范例全部是合成的。真实审稿意见及其稿件不能作为教学材料再分发，
去掉姓名的版本仍然是作者未发表的工作 —— 这也是它只教方法、不携带任何个人审稿语气的原因。
