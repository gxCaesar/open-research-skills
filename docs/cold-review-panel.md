`run-cold-review-panel` 用**没见过这个项目**的评审读您自己的稿子。它的全部价值来自
评审不知道的东西：作者对工作的一句解释，会在阅读过程中恰好补上评审本会掉进去的那个坑。

这是**入站**任务：稿子是您的，还没投出去。以受邀审稿人身份审别人的稿子是另一个 skill。

本地 [SKILL.md](../skills/run-cold-review-panel/SKILL.md) 是运行入口。

## 安装与首次调用

```bash
SKILL_DIR="$PWD/skills/run-cold-review-panel"
```

```text
使用 $run-cold-review-panel。稿件和图在 submission/ 下，artifact 在 release/ 下。
请先建 isolation-manifest，再分派五个视角，其中一个必须真跑 artifact。
```

## 隔离要证明不要声称

建一个评审目录，里面**恰好**是外部评审会拿到的东西：稿件、图、补充材料、已发布的
artifact。**不放**计划文档、调研、迭代 ledger、内部往来和早期稿 —— 那些正是会在评审
误读发生之前把它修好的材料，而那次误读才是您要观察的东西。

把该目录的列表（含文件大小）写进本轮输出，这就是 isolation manifest。

**评审自己说「我没有别的上下文」不算证据。** 模型对自身输入的陈述是它生成的一段描述，
不是它做的一次观测；无论上下文干不干净，它都会描述出一个干净的上下文。
目录列表才是那次观测。同理，「子 agent 是全新开的」要由构造和列目录证明，不是靠问。

## 五个视角

五个评审读同一样东西，产出的是同一份评审的五个副本。分派不同视角并在裁决前保持隔离：

| 视角 | 读什么 |
|---|---|
| 主张支撑 | 每条主张是否被为它提供的证据撑住 |
| 方法正确性 | 这套流程到底能不能产出报告的那个数 |
| 对比公平性 | 对比方法有没有被给到真实的机会 |
| 可复现性 | 发布出去的材料能不能让别人到达同一结果 |
| 意义 | 假设全部为真，谁会因此改变做法 |

条件允许时让视角跨**不止一个模型家族**。两个家族在不同地方失手，而它们对同一段落产生
分歧的位置，正是写作真正含混（而不只是不合口味）的位置。

## 必须有人真跑 artifact

至少一个视角是**执行**而不是阅读。"包能装上"、"命令存在"、"脚本应该能复现图 3"
都不是发现；**跑了之后发生了什么**才是发现。命令原文和输出逐字记录，包括失败。

从没碰过 artifact 的 panel 说不了可复现性 —— 那就明说，而不是让措辞暗示相反。

## 裁决与排序

meta review 不是评分平均。逐条裁决：**confirmed**（对）、**unsupported**（评审误读或
套用了本刊不持的惯例，记下理由，因为真评审也会这么误读）、**underdetermined**
（需要 panel 没有的证据 —— 那是任务不是判词）。

视角之间的一致性是弱证据：作用域重叠的视角会对最显眼的东西一致同意。由本职视角提一次的
发现，比四个读别的东西的视角附和同一句更值钱。

按「真被拒时会踩在哪一条上」排序，并为每条写出修复动作及其代价。

## 校验一轮 panel

```bash
python3 "$SKILL_DIR/scripts/check_panel_round.py" \
  "$SKILL_DIR/examples/panel-round/clean.json"
```

已知坏的那份演示它拒绝什么 —— 隔离证据是评审自述、manifest 里混进了计划文档、
没人真跑 artifact、以及 meta review 里出现录用概率:

```bash
python3 "$SKILL_DIR/scripts/check_panel_round.py" \
  "$SKILL_DIR/examples/panel-round/known-bad.json"
```

## 交付与验收

每轮一个目录，含：逐评审报告、isolation manifest、执行过的命令及输出、裁决表。
第二轮是否算冷审，取决于第二批评审有没有读过第一轮 —— 带着上一轮 meta review 进去，
那是「检查修复有没有落实」，是有用的另一件事，要标成另一件事。

**这个 panel 不预测录用。** 它看不到评审池、委员会标定和同期投稿。给出录用概率的报告
已经超出了它的证据。
