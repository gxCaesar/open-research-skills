`release-research-artifacts` 打的是**别人下载的那个包**，并且验的是**那个包**，
不是它出自的工作目录。几乎所有发布缺陷从工作目录里都看不见 —— 因为工作目录里
有那个缺失的文件。

本地 [SKILL.md](../skills/release-research-artifacts/SKILL.md) 是运行入口。

## 安装与首次调用

```bash
SKILL_DIR="$PWD/skills/release-research-artifacts"
```

```text
使用 $release-research-artifacts，anonymized-submission 模式。
结果已冻结，commit 在附件里。先出白名单文件清单给我过目再暂存。
```

## 白名单定文件集

**列出要放进去的，不要靠排除不该放的。** 排除清单是一个关于「你没想到的一切」的断言，
而没人想到的那些，恰好就是携带身份的那些：编辑器备份文件、notebook checkpoint、
缓存的凭据、写着 home 目录名的环境导出、带绝对路径的日志，以及**没有扩展名、
因此被文本扫描默认跳过的文件**。

把白名单解析成一份显式文件清单，暂存前先审这份清单。**被审过的那份清单才是产物，
生成它的那条命令不是。**

## 暂存后逐字节扫描

把白名单文件复制进一个空的暂存目录，然后扫**暂存树**而不是源树：作者姓名、机构、
邮箱、绝对 home 路径、内部主机名、项目代号、凭据与 token。

**文件内容和文件名都要扫**，容器格式内部的文本也要扫（office 文档、notebook、压缩包）。
只读已知文本扩展名的扫描器，会放过一棵缓存文件就是泄漏点的树。

**种一个应当被抓到的已知字符串，确认它真被抓到。** 干净树上报零的扫描，
和根本没在跑的扫描，输出一模一样。

## 在成品包里跑测试

把打好的包解压到一个空目录，在那里安装包自带的、锁了版本的环境规格，
然后跑项目自己的测试 / 复现命令，**不允许有任何路径指回工作仓库**。

这一步抓的是：从没提交过的文件；只因为解释器是在项目根启动才解析得了的 import；
指到包外面的数据路径；装在你机器上、不在规格里的依赖；读你 shell profile 里某个
环境变量的脚本。**在工作目录里跑通的测试，对这个压缩包什么也没证明。**

## 两种模式

**anonymized-submission**（双盲投稿）：从一个只含白名单文件的全新目录构建，
**完全不带版本控制元数据** —— 从副本里删历史，比一开始就不放进去要难验证得多。
匿名包仍然必须能跑：把标识性路径改成相对路径而不是删掉那几行，保留 licence 与
第三方声明，即使有访问权的账号是你自己也要给出数据获取路径。

**named-archive**（期刊 / 长期存档）：存进能签发持久标识符的归档，并在论文里引用那个
标识符而不是一个会变的仓库 URL；写稿件的可用性声明之前先预留标识符，好让声明能点名它。
代码与数据的 licence **分开写** —— 它们经常不同，一行盖两者通常对其中一个是错的。

## 交付与验收

交出：已审的白名单清单、暂存树扫描结果（含种入的已知字符串对照）、成品包在空目录里的
验证运行记录（命令与输出逐字，含失败）、数据卡与模型卡、引用元数据、licence 与第三方
声明，以及一份「发布了什么」的记录：逐文件大小与一个密码学哈希、构建所用的 commit、
验证时的解释器与依赖版本、平台和日期。

拿到包的人要能只凭那份记录回答两个问题：手上这份是不是同一个包，以及它由什么产生。
