# 研究到发表：贯穿真实科研的工作指南

[返回仓库导览](../README.md) · [完整 skill](../skills/research-publication-pipeline/SKILL.md)

`research-publication-pipeline` 帮您把一个研究问题推进为可信的实验、边界清楚的结论、
完整论文与别人能运行的研究材料。它面向 AI-for-biology，也适用于有明确数据、
比较协议和证据要求的计算研究。

本页解释实际科研阶段，不把填写记录当作完成研究。您可以从题目开始，也可以从已有
基线、失败实验、论文草稿或待整理代码接入；不必为了使用 skill 重走已经完成的工作。

文中的细胞扰动问题是贯穿案例：**扰动前的细胞状态能否帮助选择参考样本，从而改善
未见扰动的响应预测？** 这是说明工作方式的假设，不是已经验证的新颖方法或生物学结论。
末尾的六行合成分数只演练分析交付，不承担本页真实研究主线的证据。

按环节阅读：

- 开始工作：[调用与续接](#use) · [问题、数据、文献与路线](#question)
- 产生证据：[基线、小试、协议与开发](#comparison) · [完整实验与最终评价](#experiments)
- 形成成果：[不确定性、负结果与主张](#claims) · [完整论文](#manuscript) · [公开交付](#release)
- 局部需求：[单篇深读](#paper-reading) · [论文集合分析](#exemplar-corpus) · [单阶段请求](#single-stage) · [本地工具与教学练习](#tools)

## 怎样使用这份指南

安装统一见 [开始使用](../README.md#start)。选择 `research-publication-pipeline`，
或在支持命名技能的运行时使用 `$research-publication-pipeline`。
后面的 `text` 代码块是给 agent 的对话示例，不是终端命令。

先把当前项目说明、实际材料位置和希望完成的范围告诉 agent。
不要只说继续，也不必把全部论文与数据重复粘贴进对话。
指定允许读取的项目目录，说明哪些是当前版本、哪些是历史或冻结材料。

一个完整任务可以这样开始：

```text
使用 $research-publication-pipeline 推进我的细胞扰动预测研究。
先读我提供的项目说明、数据字典、已读论文、当前代码和最新结果。
目标是方法贡献，不把训练困难自动改成 benchmark 论文。
判断我们目前处于哪个阶段，复用仍有效的证据，只补影响下一步决策的缺口。
在当前授权范围内继续完成实验准备、分析和论文工作副本。
需要远端计算、最终测试访问、冻结原稿修改或对外发布时，列明具体待授权动作。
```

如果只想做一个阶段，直接限制范围：

```text
这次只使用 survey/plan，检查数据是否支持未见扰动预测这一问题。
请给出变量共现、独立单位、最接近工作和下一项最便宜的检查。
不要训练模型、写论文或初始化另一个完整工作区。
```

### 实际可选的十种模式

这些是对话任务入口，不是十个同名 CLI 子命令。

| 模式 | 什么时候用 | 应获得的实质产物 |
|---|---|---|
| `survey` | 调研问题与数据、深读单篇，或学习一组论文的组织方式 | 有来源的比较、Paper Card 或带出处的写作与图件观察 |
| `plan` | 需要把路线变成可执行工作 | 假设、协议、实验顺序、资源与决策规则 |
| `pilot` | 一个关键前提尚未验证 | 小规模真实数据试验及其限度 |
| `develop` | 基线和协议足以支持方法开发 | 机制实现、控制比较、失败诊断与迭代决定 |
| `monitor` | 已授权的任务正在运行 | 从日志和产物确认进展、异常或完成 |
| `freeze` | 准备固定候选与最终评价 | 候选、数据、指标、对照与测试使用规则的一致版本 |
| `claim-lock` | 结果已产生，需要决定可以说什么 | 支持、收窄、反驳或未核实的主张 |
| `handoff` | 研究阶段形成了明确结论 | 论文、负结果报告、返回题目或停止的实际交接 |
| `manuscript` | 需要完成论文而非只分析 | 完整工作稿、图表、声明、实际渲染与本地候选包 |
| `public-release` | 需要让别人运行研究材料 | 整理后的源码、说明、示例与实际复跑 |

一轮以一个主要模式为主。完整任务可以随材料推进到下一模式；
某个前提被新证据推翻时，也可以只回到受影响的阶段。

## 1. 从已有项目继续，而不是重新开题

您需要提供当前状态文件或项目说明、最近一次实际运行的输出位置、
当前使用的协议与代码版本，以及这次希望解决的问题。
如果过去有失败路线或撤回的结论，也应保留它们的身份。

skill 会先核对“正在研究什么”和“已经做完什么”。
当前项目决定优先于旧 README、聊天记忆和文件修改时间。
一个比较新的 PDF 不自动成为当前投稿稿；一个运行进程也不等于完成了实验。

```text
使用 $research-publication-pipeline 续接现有项目，不新建平行路线。
先读取当前项目说明、冻结协议、最近输出和仍开放的问题。
列出已完成且证据仍有效的部分、需要重做的部分，以及重做的具体原因。
本轮只处理当前最影响结论的缺口，保留旧的负结果和原稿。
```

有用的续接输出应能回答四个问题：
目前的科学对象是什么，哪些结果实际存在，哪项证据限制了下一步，以及需要什么操作。
不需要重新生成一套与原项目并行的状态文件。

如果项目使用本技能的初始化布局，可以从 `START_HERE.md` 找到对应记录。
这些记录帮助导航，但判断必须回到实际数据、代码、输出和已核实来源。
只改了图注时，不应重新训练模型；数据拆分变了，则要重新检查依赖它的比较和主张。

## 2. 把兴趣收窄为可检验问题

您提供的起点可以是一个失败现象、一组论文、一个可靠的数据来源，
或已有方法在某类条件下的具体限制。
“想用大模型做虚拟细胞”只能描述兴趣，尚未定义科学问题。

skill 会帮助明确输入、预测或解释对象、评价终点、泛化条件和可能的替代解释。
在贯穿案例中，需要区分：
预测未见基因扰动，预测未见细胞背景，以及同时面对二者。
这几个任务不能只靠同一个随机拆分互相替代。

```text
请把“用细胞状态改进扰动预测”收窄成一个可反驳的问题。
明确输入、输出、未见条件、主要终点和最强替代解释。
说明状态信息改变了什么计算，以及一个更简单的办法为何可能已经足够。
给出问题边界与需要验证的前提，不先给架构名称或性能承诺。
```

贡献类型也需要说清楚：

| 类型 | 主要要证明什么 | 不充分的替代证据 |
|---|---|---|
| `sota-method` | 方法改变在匹配协议和强对照下带来有意义的收益 | 只超过一个弱基线或只展示新模块 |
| `discovery` | 一个科学发现被证据支持，并有独立验证路径 | 模型预测变化或另一个模型的赞同 |
| `benchmark` | 资源或评价协议填补明确且重要的缺口 | 汇总更多数据，或方法失利后改标题 |

下一步成立的条件，是问题已经具体到可以列出必需变量与鉴别性比较。
这时还没有必要决定所有网络细节。

## 3. 数据可行性：变量要在同一可链接单位中出现

请提供数据来源和版本、许可或访问情况、元数据字典、少量可检查样本，
以及每个实验单位如何对应的说明。
只有总细胞数、数据集名称或下载链接，不足以判断问题是否可做。

skill 应检查必需变量是否共现，并区分观测行与独立单位。
不同数据集各自拥有一种变量，不意味着可以直接拼成同一个监督学习任务。

| 贯穿案例中的对象 | 需要检查的问题 |
|---|---|
| 扰动身份 | 基因、guide、剂量和时间如何记录，是否混淆不同条件 |
| 参考对照 | 对照是否与实验背景可比，表达变化相对什么定义 |
| 细胞状态 | 是扰动前可用信息，还是扰动后结果泄露出的信息 |
| 测量终点 | 基因集合、归一化和响应定义是否一致 |
| 配对关系 | 同一任务两种方法是否预测同一批有效单位 |
| 层级关系 | 细胞、guide、批次、供者、细胞系各处于什么层级 |
| 外部验证 | 另一来源是否有相同可解释终点，而不仅是相似文件格式 |

```text
只做数据可行性检查。逐项核对我们的问题所需变量是否在同一可链接实验中存在。
给出可用与缺失条件、独立单位、缺失或排除后的计数，以及能支持的拆分。
重点检查状态特征是否在预测时可获得。
不要用总细胞数代替供者或实验重复数，也不要把未找到数据写成数据不存在。
```

如果无法直接对应，应先检查其他可用来源或有科学依据的链接方式。
不能在没有合理配对时默默改用名称相近的对象。
如果仍缺少关键变量，输出应是明确的数据缺口与下一步检索，而不是失败的模型设计。

允许继续小试的，是访问、测量和可链接性有实际证据。
“文件下载成功”只解决其中一个问题。

## 4. 文献与新颖性：重建最接近工作的实际比较

请提供已读论文与代码，说明哪些来源已打开、哪些只看过摘要。
若要求在线调研，还要说明问题范围与希望覆盖的时间或来源类型。

skill 的作用是重建论文的对象、信息范围、拆分、评价和最强结论，
再比较您的具体差异，而不是把文章标题分类成相关或不相关。
单篇深读可使用内置 paper-card 组件，不依赖另一个已安装 skill。

```text
使用 survey 比较与这个问题最接近的工作。
按科学主张、机制、数据/拆分、简单基线和负结果这些角度检索。
打开支撑判断的论文、补充材料或官方代码，给出具体章节或实现位置。
区分完全相同的问题、相关但仍有可检验差异的工作，以及证据不足。
输出可用的比较表和我们必须新增的对照，不只给一串引用。
```

三个新颖性标签应有不同后果：

- `IDENTICAL`：在所选贡献类型内，关键成果已经被匹配证据建立。
- `ADJACENT`：有重叠，但仍有明确可检验差异；通常成为基线或约束主张。
- `UNCERTAIN`：现有已读证据不足，说明还需打开什么来源才能判断。

不要把“这个方向已有很多论文”当成完全重复，也不要把新模块名字当成新颖。
一个重要输出是“哪一句主张需要缩窄、哪一个对照必须补上”。
关于不存在先行工作的说法，需要说明实际检索范围和日期。

操作细节见 [调研与规划](../skills/research-publication-pipeline/references/survey-and-planning.md)。
当前最好比较方法应在题目接入和正式协议固定前分别核实，避免长期沿用旧名单。

### 单篇深读：把论文还原为可检查的 Paper Card

提供一篇论文的 PDF、DOI 或可访问页面，说明希望理解的问题；有补充材料与代码时一并提供。
内置 [paper-card 组件](../skills/research-publication-pipeline/components/paper-card/guide.md)
将科学问题、方法操作、实验比较、实际证据和局限关联起来，引用具体章节、页码或实现位置。
只读摘要、无法打开正文或未检查代码时，深读范围必须明确，不把未读材料写成已核实。

内置 [project-handover 组件](../skills/research-publication-pipeline/components/project-handover/guide.md)
回答另一个问题:**一个没参与建这个项目的人,能不能只靠这份交接包把它跑起来。**
它管两件事 —— 一次运行所处的目录契约(`run.sh` 与 `env.txt` **在开跑之前**写好,
否则第六小时崩掉的那次就不可复现),以及接手人拿到的任务清单。

```bash
python3 "$SKILL_DIR/components/project-handover/scripts/validate_handover_pack.py" \
  handover-pack.json --mode final --format markdown
```

`final` 模式要求**演练过,且演练的人不是作者** —— 作者已经知道包里漏了什么,
那恰恰是全部难处所在。另外两种答案会被判错:命令里出现绝对 home 路径或点名的远程主机
(接手人得先翻译,而翻译正是交接悄悄退化成对话的地方),以及把
"问我"写成完成判据(那不是判据,是把作者本人当判据)。

```text
使用 research-publication-pipeline 的 survey 模式，深读 paper.pdf 和 supplement.pdf。
解释论文在解决什么问题、关键方法改变了什么，以及哪些实验真正检验这一解释。
为主要结论给出页码或面板位置，区分作者主张、直接证据和您的推断。
交付 Paper Card，列出未读材料与最值得复查的限制；不启动新项目或实验。
```

### 论文集合分析：学习论证与图件组织

这与“最近相关工作是否已经做过同一课题”是不同任务。
当您已有一组论文，希望学习 Results 怎样推进、图件怎样分工、legend 需要承载哪些信息时，
`survey` 可使用随包的[论文集合分析流程](../skills/research-publication-pipeline/references/exemplar-corpus-calibration.md)。

先明确要学习的组织问题，再清点全部输入及文章类型，记录实际阅读范围。
比较同类文章的章节任务、证据依赖、主图与补充分工和图注中的样本定义，保留例外与缺失。
Article、Review、Comment 等不能无区别混算；一篇文章或一张图的重复观察也不是新增独立论文。
输出需要有页码、章节或面板位置，而不是“Nature 都这样写”的泛化结论。

```text
使用 survey 分析 papers/ 中我提供的论文集合，帮助组织现有稿件。
先列出全部输入、文章类型与实际可读部分；这轮只比较方法类 Article。
提炼 Results 的问题顺序、主图与补充的证据分工、图注如何交代采样层级。
每项观察给出来源位置，保留反例，并说明哪些做法适合当前稿件、哪些不适合。
不复制原文或图件，不把已发表先例当作当前期刊规则，也不声称统计代表整个领域。
```

得到的是带出处、范围明确的写作与制图参考；当前研究的事实和目标期刊的官方要求仍分别核对。
该任务可独立完成，不必初始化实验工作区、训练模型或进入 `manuscript`。

## 5. 发表路线：让贡献与证据要求匹配

提供期望贡献、已有证据深度和目标读者。
如果只有期刊或会议名字，skill 还需要核对当前文章类型与主流证据形态。

方法论文通常需要明确的计算贡献、强基线、跨条件泛化与机制控制。
生物学发现需要能改变科学判断的结果，以及相应独立验证。
这些是路线规划的比较维度，不是对某个期刊的录用保证。

```text
分别判断 data_feasibility、scoop_verdict 和 venue_fit。
按照我们真正计划交付的贡献，比较面向计算方法与面向生物学方法/发现的路线。
列出各自还缺的证据，而不是先选最知名的刊会。
若两条路线可共用一个科学核心，说明共用部分和各自额外验证。
```

“数据可行”“不完全重复”“适合某类刊会”是三个判断，不得相互代替。
弱 venue fit 不等于研究问题被做完了；
一个相邻方法也不意味着必须转向 benchmark。

此阶段产物应是一条明确路线、中心主张与其必要证据。
如果选择会改变科学问题或既定贡献类型，应把变化说清楚，而不是在写稿时暗中完成。

## 6. 先复现强基线，再测量值得开发的空间

请提供当前代码、数据处理、拆分、指标实现、基线配置与实际输出。
如果没有完成复现，应把“论文报告值”和“本地观测值”分开。

skill 会核对比较是否公平，安排最有信息量的便宜基线，
并检查当前最强可复现方法，而不是只让候选方法优于零预测。
简单信号能够互补时，还应考虑仅用训练信息选择的组合基线。

| 要检查的差异 | 为什么影响结论 |
|---|---|
| 输入与表示 | 候选是否获得基线看不到的信息或更强表示 |
| 预处理与数据量 | 改善是否来自数据处理而非目标机制 |
| 调参和选择 | 两者是否有可比机会选择配置和检查点 |
| 评价代码 | 是否在同一单位、掩码和方向下评分 |
| 配方复现 | 官方实现是否真正按适用设置运行，而非只用了同名模型 |
| 资源 | 速度或效率主张是否使用一致的计算条件 |

```text
先检查基线复现与候选方法是否同任务、同信息、同评分。
复用项目内已有的可靠结果，指出仍未匹配的配方差异。
按适用性比较扰动盲、训练响应均值、简单回归、组合基线和当前强方法。
再用真实可支持的上界与误差尺度判断 headroom，不先增加模型复杂度。
```

headroom 是相对可解释的经验上界还剩多少有意义的空间，
不是指标理论上还没到最大值。上界可以来自合适的重复测量或可解释的参考条件，
但必须说明该界限怎样获得、与当前任务是否相容。

若改善小于测量或实现差异，继续调模型可能只是追噪声。
若强基线没有跑对，则先修复复现；这时不能宣布任务没有空间。
下一步需要的是实际比较证据，而不是写着 OPEN 的状态字段。

## 7. 小试：跑通一条完整且有判断价值的链

您提供一个代表性真实子集、可执行基线和准备检验的关键前提。
小试应覆盖读取、预处理、执行、评价和输出，而不是只证明模型能做一次前向计算。

```text
用 pilot 检验目前最关键的前提：状态匹配是否在计划的未见扰动条件下仍有可辨别作用。
先固定小试数据、评价单位、主要终点、对照和正负结果的解释。
选择能跑完整流程的最小真实子集。
只执行已授权的本地分析；若需要新计算权限，完成配置和输入检查后列出精确请求。
```

合成数据适合检查工程行为，但不能替代真实数据的小试。
能在小输入上训练，不等于能够按目标协议复现强基线。
必要时应单独检查关键实现的数据可读性、环境与评价路径。

小试报告要同时给出输出和决定：
实际观察了什么、是否支持此前提、偏差来自哪里，以及扩大实验会多解决哪项不确定性。
正向小试支持的是所测试前提，不自动证明最终泛化或新颖性。

出现非有限损失、异常高分或标签/拆分不符时，应保存原始证据并调查。
这类异常不是值得直接扩大实验的好结果。

## 8. 固定协议：让后续比较含义不变

提供经过检查的数据、基线、小试结果和准备检验的中心假设。
目标是让研究者能够在观察结果前回答“怎样算支持，怎样算未支持”。

协议至少需要共同确定：

- 数据与标签版本、预处理、缺失和排除规则。
- 真正的独立单位、训练/开发/最终评价拆分和信息边界。
- 主要指标的实现与方向，以及辅助指标的用途。
- 比较方法、配置选择、停止和检查点选择规则。
- 重复运行的汇总方式，以及真实实验单位上的不确定性方法。
- 有限的开发预算、候选选择规则和最终测试使用安排。
- 哪些字段允许工程性修复，哪些改变意味着换了科学协议。

```text
使用 plan/freeze 把已决定的比较写成可执行协议。
明确唯一主要终点、独立单位、候选选择、全部重复运行的汇总和允许的排除。
给出支持、反对、无法区分的解释，以及下一步采用哪个决定。
锁住最终测试使用方式，不让开发结果反过来改变终点或选择规则。
```

正式评分前，应有一个已知答案案例和一个能被拒绝的污染或泄露案例。
这里只要求针对真实风险验证一次，不要求为没有出现过的问题建立一整套新框架。
如果检查器拒绝了真正有效的输入，先查看原因，不直接放宽它来获得通过。

协议本身不授予计算权限。它的作用是使随后每次实验都能回答同一个问题。
进一步说明见 [协议与方法开发](../skills/research-publication-pipeline/references/protocol-headroom-and-development.md)。

## 9. 方法开发：从错误诊断到最小机制

您提供开发集逐单位误差、失败条件、当前基线和冻结协议。
只给一个总体均值，通常不足以选择下一个方法变化。

skill 会先区分问题来自数据上界、配方不匹配、优化失败、信息泄露、
表示不足还是特定条件下的误差，再提出能够区别这些解释的候选。
模型模块应对应一个已诊断问题。

```text
使用 develop 阅读开发集误差和冻结协议。
先定位最高信息量的失败条件，比较至少两个真正改变不同计算机制的候选。
每个候选说明：改变对象、预期影响条件、同信息对照、负结果如何反驳解释。
先处理配方、目标、数据/表示等较低成本原因，再考虑架构。
本轮只实现并检验一个已选定变化，不同时换数据、损失和指标。
```

在贯穿案例中，状态匹配与额外信息是两个竞争解释。
合适的控制应移除状态匹配本身，同时尽量保持其他相关条件。
把一个更小、更差输入的模型当作对照，无法独立归因于状态匹配。

建议采用的开发顺序是配方公平、目标对齐、数据或表示、组合、测试时计算，
最后才是架构。它避免用架构复杂度掩盖低层问题，不表示所有项目必须逐项增加模块。

每次比较应产出可重算结果、对照解释与一个下一步决定。
`REVISE` 是同机制的一项有依据修改；`PIVOT` 是换到不同候选。
冻结预测条件下两次失败应停止继续修补该机制，但不自动否定仍有空间的整个任务。

<a id="experiments"></a>

## 10. 完整实验与监控：把计划变成终止证据

完整实验需要实际代码、最终配置、数据与输出位置、重复运行安排，
以及估计过的资源、恢复方式和终止条件。
skill 可以帮助准备和检查这些内容；公共版本不附私人远端启动器。

```text
基于已选候选和冻结协议，准备完整实验的命令、配置与产出清单。
覆盖全部预定比较、重复运行、机制控制和验证，不增加结果导向的新筛选。
说明数据准备、训练、评价、磁盘、内存和计算成本。
实际启动前确认对应授权；结束后用日志、退出码和结果文件检查完成情况。
```

已授权运行后，可以单独调用 `monitor`：

```text
只监控当前已授权运行。读取它的实际日志、输出和退出状态。
确认早期数值是否有限、是否出现协议偏离，以及预期结束产物是否齐全。
正常进行时不要重复请求科学决策。
若出现异常，保留失败证据并说明受影响的比较，不悄悄换配置继续。
```

完成的证据包括正确任务的终止状态和预期产物，
不是进程存在、旧的完成标记或代理声称已经跑完。
保留失败、中断、无效与未运行的试验；完整结果不能只由成功目录拼成。

工程修复只有在科学协议不变时才是同一次比较的修复。
调整样本、基线、损失或评价方式可能改变主张，应单独说明。

## 11. 最终评价：保护开发与确认的分界

提供已选候选、固定配置、完整开发记录、对照结果与最终测试安排。
使用 `freeze` 确认信息边界和评价准备，而不是让最终测试帮您选择模型。

```text
在访问最终测试前核对候选、配置、比较方法、指标、排除和统计规则是否完全固定。
检查所有必要的基线与机制控制是否已经完成。
区分最终确认与开发分析，并列出任何已经暴露的测试信息。
本次只做准备检查；最终测试访问沿用单独的授权安排。
```

测试暴露不只是拷走标签。逐例反馈、可泄露结局的排序、
反复排行榜反馈和隐藏分组信息都可能影响选择。
若最终测试已参与选择，应如实更改证据性质，而非继续称为未触碰评价。

观察最终结果后按事先规定的全部条件判断。
如果协议要求总体改善、预定切片、对照、不确定性和效率同时满足，
不能只选其中有利的几项。

未通过最终比较时保留失败。新的开发需要新的假设或未触碰评价边界，
不能把同一个最终结果再当开发反馈无限循环。
详见 [冻结评价](../skills/research-publication-pipeline/references/frozen-evaluation.md)。

<a id="claims"></a>

## 12. 不确定性与负结果：决定证据能走多远

请提供逐单位预测、成对比较、实验层级、有效单位数、排除与缺失记录，
以及所有预定重复运行。只有均值和一个 p 值无法重建这些内容。

skill 帮助核对统计量到底对应哪个总体，区分生物学重复和计算随机性，
并检查区间、检验和多重比较是否与冻结协议一致。
它不能为了填满论文统计字段而更改已经固定的分析。

```text
阅读原始逐单位结果和统计协议，核对主要比较的不确定性。
明确 n 指什么，重复种子与实验单位怎样区分，哪些单位因何被排除。
把负向、无差别和未运行结果分别保留。
若分辨率不足，说明依据；不要把不利点估计自动改称有潜力。
```

| 实际证据 | 可以考虑的下一步 |
|---|---|
| 主要结果与机制控制都支持限定假设 | 进入必要的独立验证和主张整理 |
| 总体改善但机制控制未支持 | 保留性能观察，收回或修改机制解释 |
| 差异在预定分辨率下无法区分 | 如实报告不确定，按原规则决定是否补证 |
| 预定条件下明确失败 | 停止该机制或转入有依据的替代候选 |
| 数据或协议异常 | 先处理异常，不能据此宣布科学路线耗尽 |
| 可测空间已关闭或预算耗尽 | 形成范围明确的停止或负结果报告 |

置信区间和检验需要与实际独立单位匹配的方法。
本指南不指定一个对所有单细胞、分子或临床任务都正确的公式，
也不把细胞数、随机种子或多个评分器当作额外独立证据。

## 13. 形成主张：把观察、解释和未知拆开

这一阶段提供的是最终结果、方法定义、直接来源与限制，
不是希望论文讲出的结论。
使用 `claim-lock` 把每句话绑定到它真正依赖的证据。

```text
根据冻结结果整理论文主张。
逐条给出比较对象、数据/人群、拆分、指标、方向、结果位置和不确定性。
区分方法描述、实测结果、机制解释、已有工作与限制。
标出支持、需要收窄、被反驳和未核实的句子，给出可以保留的最窄表述。
```

例如，限定背景中的预测改善不自动支持跨组织泛化，
计算控制支持也不自动等于独立生物学发现。
“我们观察到什么”与“这可能解释什么”应在文字中可区分。

`handoff` 随后决定交接的是论文材料、负结果、返回题目的理由还是停止报告。
负结果可以成为有用的研究输出，但不会自动变成 benchmark 贡献。
如果完整任务要求完成论文，交接记录不是终点。

<a id="manuscript"></a>

## 14. 写完整论文：从证据结构到实际候选文件

请提供锁定主张、完整实验、原始图表来源、当前投稿要求与允许编辑的工作副本。
如果还没选定 venue，可以先整理科学结构，但不能声称满足某一正式版式。

```text
使用 manuscript 根据已锁定证据完成新的论文工作副本。
先明确中心问题、各节任务和每个结果段落对应的输出。
写完整 Introduction、Method、Experiments/Results、Discussion 与必要限制，
按实际文章类型调整结构，不强加三个贡献。
继续完成图表、图注、引用、数据/代码说明、声明、实际构建和逐页检查。
保留原稿，明确尚缺作者确认或尚未运行的工作。
```

应有的工作包括三个层次：

1. 科学结构：准确的问题、已有工作边界、方法为何这样计算、比较如何检验它。
2. 可复现内容：数据、处理、拆分、基线、拟合与选择、评价、资源和不确定性。
3. 实际交付：完整可编辑源稿、图表与图注、补充材料、真实渲染文件和所需声明。

图形需要区分来源数据图与方法示意图。
数值面板从已核实分析输出作图，不用生成图像伪造实验；
示意图保持对象、箭头含义和计划/已完成区别，并检查可编辑源与最终导出。

标题和摘要在论证稳定后压缩，不创造新的结果。
数据仓库、伦理、作者贡献、基金和 AI-use 信息只能来自实际确认，
不能从邻近项目或模板自动补齐。

当前工具无法构建某种格式时，交付可编辑源并说明缺失步骤；
Markdown 工作稿不等于已经生成正式 PDF。
详见 [完整论文路径](../skills/research-publication-pipeline/references/standalone-manuscript.md)。
会议、期刊与可视化 skill 可增强专项能力，不是完成本地范围的强制依赖。

<a id="release"></a>

## 15. 可复现公开交付：让新读者知道怎样运行

请提供准备公开的代码、可再分发数据、依赖、真实运行命令与许可信息。
研究工作区往往包含读者不需要或不能公开的材料，不能整目录导出。

```text
使用 public-release 整理研究代码的本地交付副本。
从明确文件清单建立 public-release/，包括运行所需源码、配置、依赖版本、
小例子、数据获取和预处理、预期输出、测试、许可和真实论文引用信息。
在新位置按 README 执行适当的小规模复跑，核对文件、数值和解释。
说明完整训练与大数据步骤哪些没有重跑；不把小例子称为独立科研复现。
本轮不创建远端仓库、推送、上传或发布。
```

一个有用的公开包，应让读者依次知道：
需要什么环境、如何取得数据、怎样运行、应看到什么、结果有什么限制。
有运行脚本却没有输入定义，或者只有 notebook 截图，都不足以完成这种交付。

源码包只保留用户需要的内容。私有数据、个人路径、控制记录、提示材料和运行轨迹
留在公开副本之外。引文不等于再分发许可，第三方文件需按其真实条款处理。

复跑应使用交付副本本身，而不是依赖原项目的隐式路径。
观察到的小例子运行成功、全量科研复现、远端已公开与论文已提交是不同事实。
详细要求见 [公开代码交付](../skills/research-publication-pipeline/references/public-code-release.md)。

## 16. 按阶段提出一个小请求

不需要每次都让 skill 接管全流程。下面的范围可以直接替换为您的材料：

| 当前问题 | 有用的请求边界 |
|---|---|
| 有论文但题目不清楚 | 只重建最接近工作的比较与未解决条件 |
| 有数据但不知道能做什么 | 只检查共同变量、链接单位和可测试问题 |
| 基线跑不出报告值 | 只诊断配方与评价差异，暂停候选改进 |
| 新方法均值较好 | 检查配对结果、机制控制和真实不确定性 |
| 一项实验失败 | 识别失败层级，提出一个有依据的下一步 |
| 已有完整结果 | 整理主张、论文结构和缺失验证 |
| 稿件需要补充说明 | 只审阅指定章节，不扩大为新实验 |
| 代码要交给读者 | 只整理和复跑公开副本，不发布 |

单阶段产物也应说明实际观察、仍未运行的工作和下一步。
它不需要附带一套空白计划，也不要求重新核验所有无关阶段。

## 附录 A：本地工具能做什么

本技能依靠 agent 阅读来源、研究者判断和项目工具执行科学工作。
下列脚本提供辅助能力，不是预装好的方法训练系统。

| 工具 | 实际用途 | 不能代替什么 |
|---|---|---|
| `init_publication_project.py` | 建立明确未完成的新工作区 | 数据核验或课题批准 |
| `validate_publication_project.py` | 检查指定范围的记录与局部文件 | 科学真实性、训练和论文渲染 |
| `render_evidence_figure.py` | 按本地规格绘制小型来源图形 | 新的统计分析或图形质量判断 |
| `examples/perturbation-comparison/analyze_scores.py` | 合成配对分数的描述性汇总 | 模型训练、SOTA 或生物学验证 |
| `examples/run_demo.py` | 合成记录与可选算术打包冒烟演练 | 一个完整研究项目 |

以下命令都从 `open-research-skills` 仓库根目录运行。
如果之前进入了其他目录，先回到仓库根目录。
命令采用 macOS/Linux shell，Python 3.9+；初始化和教学分析只需标准库。

```bash
SKILL_DIR="$PWD/skills/research-publication-pipeline"
DEMO_OUT=$(mktemp -d)
python3 -B "$SKILL_DIR/scripts/init_publication_project.py" "$DEMO_OUT/project" \
  --project-id perturbation-study --title "未见扰动响应预测的状态匹配比较" \
  --domain single-cell --contribution-lane sota-method
python3 -B "$SKILL_DIR/scripts/validate_publication_project.py" "$DEMO_OUT/project" \
  --target working --format text
```

新工作区可以通过 working 结构检查，同时保留未完成研究。
上述新建示例预期为 `PASS_WITH_WARNINGS`，并提示数据、协议、headroom 和主张尚未完成；
这些警告是实际缺口，不是需要改成通过的装饰性字段。
`pilot`、`development`、`handoff`、`public-release` 是其他记录检查目标，
不是要求按顺序把空字段改成通过。

## 附录 B：用六行合成分数练习结果交付

这个独立小练习展示读取数据、保留负差、生成汇总与说明。
分数是任意设定的 synthetic 教学数据，任务标签不代表真实基因、供者或实验重复。

```bash
# 从仓库根目录运行。
SKILL_DIR="$PWD/skills/research-publication-pipeline"
DEMO_OUT=$(mktemp -d)

```

随附输入得到六个差：+0.02、+0.01、−0.01、+0.02、+0.01、−0.02。
`differences.csv` 保留逐任务数据；`summary.json` 给出 4 正、2 负、0 平，
平均差 +0.005；`summary.md` 根据实际计数生成有边界的中文说明。

它不计算置信区间，不训练模型，也不构成前面任何真实科研阶段的完成证据。
