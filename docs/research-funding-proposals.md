# 基金 proposal：从科学问题到申请材料

[返回仓库导览](../README.md) · [完整 skill](../skills/writing-funding-proposals/SKILL.md)

`writing-funding-proposals` 面向科研基金 proposal 的撰写，主要覆盖 NSFC 与省级基金，支持
证据整理、选题比较、科学论证、章节任务、计划与预算核对、申请人草稿审阅和本地交付。
广东是随包提供的省级基金示例；其他省份按实际省份、年份和项目类别自定义适配。
其他中国科研基金项目仍可使用通用流程，但不是本入口的主要定位。
它帮助申请人建立一份可信、可执行的方案，不预测中标，也不把填完表格当作论证成立。

本页使用细胞扰动预测作为贯穿案例，重点解释各阶段怎样实际工作。
你可以只请它审阅立项依据，也可以从一个新问题组织完整申请材料。
已有材料可靠时，应从当前阶段继续，不必重新生成一套申请流程。

按环节阅读：

- 接入申请：[调用、项目范围与辅助政策](#use) · [选题、证据与申请方向](#topic)
- 建立论证：[立项依据与研究内容](#argument) · [方案可行性与前期基础](#feasibility)
- 安排交付：[年度计划、风险与预算](#plans) · [章节任务与图表](#sections) · [审阅与最终材料](#review)
- 局部需求：[单阶段请求](#single-stage) · [本地工具与合成练习](#tools)

## 怎样调用，以及先确认什么

安装统一见 [开始使用](../README.md#start)。
选择 `writing-funding-proposals`，或在支持命名技能的运行时使用
`$writing-funding-proposals`。
下文 `text` 代码块是对话示例，不是终端命令。

先提供目标资助机构、年份、项目类别、当前指南和机构要求。
科学材料包括已有问题、可用数据、已读论文、申请人真实成果与当前草稿。
材料不完整可以先整理缺口，但不能把未知字段补成有利事实。

### 实际支持的项目范围

| 入口或参数 | 当前技能提供什么 | 真实申请还需确认什么 |
|---|---|---|
| `nsfc` | 国家自然科学基金（NSFC）路由与随包的 2026 年参考快照 | 目标年份、具体项目类型、指南、系统字段与机构要求 |
| `guangdong` | 省级基金的广东示例与随包的 2026 年参考快照 | 当期通知附件、类别、资格、期限、预算与实际模板 |
| `other` | 其他省份的自定义适配，以及其他基金的通用流程 | 实际省份、资助机构、年份、类别及其当前规则，不继承广东或 NSFC 的政策 |

参数支持某个项目不意味着已经证明你符合资格，也不代表已有每个省份的预设。
非广东的省级基金走 custom（自定义适配）流程，现有命令参数是 `--program other`，
不是 `--program custom`。应按目标省份、年份和项目类别读取主管部门指南、附件、
实际系统模板和机构要求，逐项确定资格、代码、期限、金额、章节及 AI 辅助范围；
不能把广东或 NSFC 的规则照搬过去。

```text
使用 $writing-funding-proposals，协助准备浙江省级基金申请。
先从我提供的当年通知和附件确认目标年份、项目类别、实际模板与机构要求，
按自定义适配处理，不套用广东或 NSFC 规则；需要初始化时使用 --program other。
本轮整理科学问题、前期证据和章节任务，并审阅我的草稿。
正文与图形辅助权限分别核实；未核实时只做证据、brief 和审阅，
不把未公开材料发送到外部图像服务。
```

### AI 辅助范围必须来自适用来源

本技能有两种辅助模式：

- `EVIDENCE_AND_AUDIT_ONLY`：整理来源、问题、比较、章节任务并审阅申请人草稿。
- `ASSISTED_DRAFTING_ALLOWED`：只有当前基金与机构来源明确允许相应辅助，才进入限定起草范围。

未核实的情形按第一种执行。
这不是要求停止科学准备，而是不能把证据整理改名为润色后输出可直接提交的生成正文。

本版本的 [NSFC 2026 参考快照](../skills/writing-funding-proposals/references/profiles/nsfc-2026.md)
根据其记录的来源，将该快照的辅助模式设为 `EVIDENCE_AND_AUDIT_ONLY`。
[广东 2026 参考快照](../skills/writing-funding-proposals/references/profiles/guangdong-2026.md)
未据其已检查通知建立生成式 AI 起草许可，也保留证据与审阅范围。
这是本版本如何执行的说明，不代表本页刚完成目标年份的在线政策核验。

具体使用应重新阅读适用的基金通知、机构要求和所涉条款。
授权写作不自动意味着授权 AI 图形；申请人仍需确认事实、本人角色和必要声明。
关于记录范围的说明见 [来源与辅助政策](../skills/writing-funding-proposals/references/authority-and-policy.md)。

## 1. 接入申请：把官方要求和科学材料分开

请提供目标年份与类别的指南、附件、实际系统模板、机构通知，
以及申请人希望本次完成的任务。
历史获批申请可以帮助理解表达或非表达性的结构，但不能充当当前规则。

skill 会区分哪些要求来自官方来源、哪些来自机构，
以及哪些只是旧模板或经验。
它还会识别资料是否可以公开、只能在申请人项目内处理，或属于受限保密材料。

```text
使用 $writing-funding-proposals 接入这个申请。
先核对我提供的年份、项目类别、指南附件、机构通知和实际模板是否匹配。
列出目前可确定的要求与需要打开来源核实的事项。
确认本次允许的辅助范围；政策未核实时只做证据、结构与审阅。
把科学材料与行政要求分开，不从旧项目继承资格、经费或申请人信息。
```

应得到的是一份适用要求说明与明确缺口，
而不是看似完整却混入不同年份和项目类别的规则表。
如果当前系统模板尚未取得，可以继续做科学问题与结构工作，
但不能宣称最终格式已经正确。

能进入科学准备的，是你已清楚本次做什么、用哪些材料、哪些输出被允许。
进入正式交付前，还需核实最终使用的实际模板与适用来源。

## 2. 从已有草稿继续：只重开受影响的部分

如果已经有申请书，请提供当前主稿、最近修改说明、所用模板、
最新审阅意见和对应证据。
指出哪些内容已经由申请人确认，哪些只是早期占位。

```text
继续这份已有申请，不重新开题。
先读当前草稿、科学问题说明、证据材料和上一轮审阅意见。
判断这次变化影响了哪些章节、图表、年度安排和预算。
保留不受影响的材料，只处理仍未解决或被新证据推翻的部分。
输出实际修改任务和补证清单，不把旧完成状态当成现状。
```

例如，换了验证数据可能影响研究内容、可行性、图示和年度计划，
但不一定改变每个背景段落。
一个项目周期的变更会影响任务与预算安排，不能只改封面上的年份。

你应收回一份清楚的续接决定：当前科学问题、材料可信度、
本轮工作范围和完成依据。
不能根据文件最新时间自动选择申请主稿。

## 3. 选题：从模型愿望到科学问题

请提供一个具体观察、现有方法的限制、可用数据或研究能力。
如果起点只是想做一个大模型，skill 需要帮助找到可回答的问题，
而不是立即给项目取一个更响亮的名字。

贯穿案例的初始愿望是改进细胞扰动预测。
可以收窄为：

> 在未见基因扰动的响应预测中，利用扰动前细胞状态限定参考样本的选择，
> 能否改善预测，并区分状态匹配的作用与额外信息的作用？

这仍是一个待验证问题。它不证明状态匹配是新颖机制，
也没有预设正向结果或数据已经存在。

```text
围绕我已有的数据与能力，梳理这个细胞扰动预测问题。
明确对象、未见条件、预测终点、候选作用和最强替代解释。
比较真正不同的少量候选，不为凑数量制造弱选题。
分别给出科学价值、数据可行性、申请人匹配、最接近工作和最便宜的补证。
暂不写申请正文或承诺效果数值。
```

应形成能指导数据检查与比较设计的问题说明。
一个好问题能够告诉读者什么结果会使假设不成立。
项目标题则压缩这个已经明确的问题，而不是用标题反过来决定内容。

如果候选只在模型品牌或术语上不同，应合并后比较。
若最便宜的方法已经解释了改进，问题可能需要收窄或改变机制，
不宜直接转入更复杂的模型设计。

## 4. 证据与最近工作：找到准确的差异

请提供关键论文、补充材料、实际代码和数据说明。
只有摘要或搜索结果时，应把未检查部分保留为未知。

skill 会逐项核对关键前提的证据，
区分已有工作真正做到什么、在哪种条件下仍未回答你的问题。
这比按照年份罗列文献更有助于立项依据。

```text
检查支撑中心问题的来源和最接近工作。
重建它们的数据、信息范围、拆分、终点、对照和最强结论。
说明我们要检验的差异是科学对象、计算机制、验证条件，还是只是表述变化。
保留相邻工作，把应加入的强对照和需要收窄的句子写清楚。
未打开的材料不要标成已核实。
```

在方法、发现或资源贡献各自范围内，
`IDENTICAL`、`ADJACENT` 和 `UNCERTAIN` 有不同含义。
相邻工作通常会改变对照和措辞，但不自动否定课题。
反之，没有搜到同名模型也不能证明创新。

还要区分问题出在论述、数据还是任务本身。
如果只是数据访问未落实，产物应说明如何补证，而不是宣称科学问题已无价值。
操作细节见 [证据、选题与路线](../skills/writing-funding-proposals/references/evidence-topic-and-route.md)。

## 5. 申请方向和代码：由新知识与验证对象决定

请提供当前指南里的候选方向、代码和系统选项，
以及你的中心问题、主要产出与最终验证。
不要只根据题目出现 AI、组学或 GPU 来选信息科学方向。

```text
基于当前官方选项，比较最合理的申请方向与代码。
逐项说明中心新知识、主要产出、验证终点、自然评审群体和最大不匹配。
检查题目、关键词、研究内容与方向是否一致。
不凭旧经验填代码，也不把路线上尚未解决的分歧写成最终选择。
```

如果主要贡献是算法，应能解释计算上的新问题与鉴别性比较。
如果主要贡献是生物学发现，应有相应的发现证据和验证路径。
跨学科不是同时写两套互不相干的目标。

应收回的是有依据的路线建议与未解决问题。
最终路线要与申请人的真实资源和申报范围相符，
不能为了适配某个代码改变已冻结的科学承诺而不说明。

## 6. 立项依据：把价值、现状与问题接起来

请提供已核实的关键来源、选定问题、最近工作比较，
以及申请人已有的立项依据草稿。
在证据与审阅模式下，skill 返回段落任务与具体审阅意见，不生成提交正文。

立项依据需要解释一个项目特定的困难：
为什么值得研究，现有办法支持了什么，
在哪个明确条件下仍存在问题，以及本项目准备怎样回答。
泛泛介绍 AI 发展趋势不能替代这条论证。

```text
只处理立项依据。
根据已核实来源和当前问题，给出逐段任务：每段要建立什么前提，
使用哪些证据，怎样连接到下一段，哪里还缺材料。
审阅我现有文字中夸大最近工作不足、缺少比较边界或提前宣称结果的句子。
输出修改任务，不生成可直接粘贴的申请正文。
```

贯穿案例可按以下逻辑组织，而不是按固定句式扩写：

| 段落任务 | 应回答什么 | 缺失时怎样处理 |
|---|---|---|
| 定义困难 | 哪种未见扰动预测失败会影响后续判断 | 补实际任务与来源，不先谈普遍重要性 |
| 界定已有能力 | 最接近方法使用了哪些可用信息 | 阅读方法和评价，不只引用结论 |
| 找到未解决条件 | 状态匹配与额外信息是否被区分 | 将同信息控制变成拟研究比较 |
| 提出中心问题 | 什么比较可以支持或反驳假设 | 明确终点和可能的失败结果 |

这一节完成的依据，是读者可以从来源走到中心问题。
文字更顺或引用更多，不等于逻辑已经闭合。

## 7. 研究内容：每项都对应一个必要判断

请提供选定问题、数据对象、候选机制、鉴别性比较与计划产出。
内容数量由科学依赖决定，不因为某个模板有三部分就必须有三个研究内容。

```text
把中心问题组织成最小完整的研究内容。
每项写清对象、方法或机制、鉴别性验证、可交付产出和失败后的处理。
说明各内容之间的依赖，合并只是换名重复的工作。
不要把平台搭建、收集数据或性能目标单独当成没有科学问题的研究内容。
```

贯穿案例可以有核心比较 C1 与独立背景边界验证 C2。
C1 检验状态匹配是否提供额外价值；
C2 检查该结论在事先确定且测量可比的背景下适用到哪里。
C2 依赖 C1 的方法定义，不能另换一个模型再称为同一结论的验证。

数据准备通常是进入比较的前提，不自动成为主要贡献。
有独立缺口与科学用途的资源建设可以成为贡献，
但需明确论证，不能因为方法开发困难就默默换题。

skill 的论证关系用 Q/C/V/O/CL/F 表示：
问题、内容、验证、产出、已有证据与图。
这些标识用于保持一致，不要求申请正文堆满代号。
详细结构见 [论证与章节](../skills/writing-funding-proposals/references/argument-and-sections.md)。

## 8. 研究方案与可行性：说明怎样执行和怎样判断

请提供真实数据可用性、方法依据、现有实现、测量条件和资源约束。
可行性不是列出服务器、实验平台和合作者名字，
而是说明关键依赖为什么可获得、可执行、可检验。

对细胞扰动预测，应同时检查扰动身份、背景状态、参考对照、
表达终点和实验层级。不同来源分别拥有这些变量，不代表已经形成配对数据。

```text
审查研究方案的可行性。
核对必需变量是否在同一可链接实验中出现，独立单位与评价边界是什么。
检查状态信息在预测时是否可获得，参考样本是否越过训练边界。
把方法依据、实际可执行条件、尚未落实的资源和最关键风险分开。
为每个关键前提给出最便宜的验证及未通过后的行动。
```

公平比较应说明哪些条件保持一致，
不能让候选获得额外数据再把效果归因于某一机制。
强基线需要实际可复现版本和合理的调参机会；
弱基线不能因为容易跑通就成为唯一比较对象。

| 方案部分 | 有用的可行性证据 |
|---|---|
| 数据 | 实际访问、字段与配对检查、独立单位和缺失情况 |
| 方法 | 与候选变化相符的依据、可运行路径与适用限制 |
| 评价 | 明确终点、同信息对照、拆分和真实不确定性单位 |
| 独立验证 | 测量可比性、访问条件、人员职责与执行安排 |
| 资源 | 任务所需的人力、实验与计算成本有来源或测量 |
| 风险 | 在依赖工作前识别问题，有仍能回答科学问题的处理方式 |

应收回一份区分已具备、可迁移、拟开展和未落实条件的方案。
没有实测结果时，可以承诺执行比较和报告其有效结果，
不能承诺必定得到某个提升或机制发现。

## 9. 前期基础：把申请人的真实贡献对应到任务

请提供直接可查的成果、实际分析或实验记录、
本人角色、可用数据与资源证明。
论文列表、作者排序和文章题目只能支持有限的书目信息，
不能自动证明申请人完成了关键技术或已落实合作。

```text
只整理前期基础与本项目任务的对应。
根据我提供的真实材料，区分已完成工作、可迁移能力、拟开展工作和缺失证据。
逐项说明申请人实际承担了什么，能够支持 C1/C2 的哪个依赖。
删除从作者位置、平台名称或邻近项目推断出的能力和资源承诺。
返回证据映射与章节修改任务，不编写不存在的前期结果。
```

有用的基础说明不是把所有成果都搬进申请。
一个成果应解释它支持数据处理、计算机制、验证能力还是资源条件，
并保留原成果的人群、任务、样本量、比较和本人作用。

贯穿教学案例没有申请人证据，因此该部分只能指出需要哪些材料。
不能将合成演示的分数、占位图或记录检查通过写成已有基础。
经费编号、伦理状态、数据许可和机构支持也不得从其他项目复制。

下一步成立的，是关键任务具备可核实的能力或明确的补齐方式。
不能仅靠流畅的叙述把缺失依赖写成可行。

## 10. 年度计划：承诺可交付工作，而不是正向发现

请提供实际项目周期、研究内容依赖、人员安排和已有资源。
skill 会把年度任务、验收产出与风险对应起来，
检查有没有把本应提前确认的前提安排在后期。

```text
按当前项目的真实周期安排年度计划。
每项说明所属研究内容、前置条件、可验收产出、完成依据和风险。
区分主线交付、谨慎探索和早期边界确认。
承诺完成公平比较并报告结果，不承诺固定提升、必然发现或某刊录用。
```

三类承诺的用途不同：

| 类型 | 什么时候用 | 必须说清楚 |
|---|---|---|
| 主线交付 | 中心问题需要且资源基础支持的工作 | 交付物、验收证据、依赖与有科学意义的替代方案 |
| 谨慎探索 | 非必需但可能有价值的扩展 | 有限投入、可反驳假设与何时停止 |
| 边界确认 | 后续范围是否成立尚需早期检查 | 最小检查、继续与不继续条件、影响哪个后续任务 |

同一研究内容的第一年可能是边界确认，后续才进入主线。
这些分类不是给所有工作贴相同标签，也不是让必要验证变成可有可无的探索。

贯穿案例若用假想三年期，可在第一年核对数据和基线，
第二年完成 C1，第三年完成已确认可行的 C2 并整理材料。
这只是教学安排，不是 NSFC 或其他基金统一规定的项目期限。

## 11. 风险：给出触发条件与科学上有用的处理

请提供最不确定的数据、方法、验证或资源依赖。
风险部分应让读者知道何时发现问题、影响什么、怎么处理，
不能每一项都以继续优化作为结尾。

```text
检查年度计划中的真实技术风险。
每项给出来源、最早可观察信号、影响的任务、检查时点与替代方案。
判断替代方案是否仍回答原问题，或已经需要申请人决定改变范围。
不要把隐藏负结果、换指标或降低基线写成风险应对。
```

| 贯穿案例的风险 | 最早检查 | 合理行动 |
|---|---|---|
| 状态与扰动无法链接 | 访问与元数据检查 | 补查来源；仍不可行则调整问题 |
| 基线已解释可测改善 | 公平复现与误差尺度检查 | 修改机制或问题，不用增加参数掩盖 |
| 效果来自额外信息 | 同信息控制 | 先修正比较，再解释状态匹配 |
| 独立背景不可获取 | 开始阶段确认访问与测量 | 限定结论，不以内部重复代替 |
| 计划超出资源 | 按任务估计与小规模测量 | 调整执行安排，明确科学范围影响 |

风险表与章节、图示和年度计划应一致。
如果一处把外部验证写成必需，另一处却称为可随时取消的探索，
那是科学依赖矛盾，不是措辞问题。

## 12. 预算：先确认需要什么，再检查任务与金额

请提供当前项目类别的预算规则、机构要求、实际任务、资源估计、
可支持价格或成本的来源，以及申请人确认的信息。
不要让 skill 根据旧项目金额自动凑出一个看起来合理的总额。

是否需要财务预算、采取什么方式、使用哪些费用类别，
由当前基金和项目类别的适用来源决定。
本技能不提供通用经费额度或统一预算科目。

```text
根据我提供的当前预算规则，先确认该项目是否需要财务预算及其编制方式。
若需要，把真实任务与所需资源对应到适用类别和年度安排，
检查总额、分类额与年度额是否一致，说明各项依据与尚缺报价。
若规则或成本未核实，返回待核实事项，不虚构额度或调金额使表格通过。
```

预算检查要同时看到算术和科学内容：
合计正确但不支持关键实验，仍不是可行预算。
某项计算或测量费用没有任务来源，也不能仅因类别允许就随意加入。

如果当前类别不要求某种预算表，应根据真实来源说明，不制造无用表格。
如果有合作、配套或管理要求，应读取其适用条款，
不能把别的基金做法当作默认答案。

年度计划改变后，只需重查受影响的任务与费用。
预算平衡不能证明成本真实、支出合规或申请人具备相应资源。

## 13. 章节任务书：给每段一个具体工作

请提供已经稳定的科学问题、比较方案、证据与章节要求。
章节任务书不是标题列表，而是让申请人知道每段解释什么、
需要引用哪项证据以及哪些事实尚不能写。

```text
为立项依据、研究内容和研究基础生成带批注的章节任务书。
逐段写清论证任务、证据位置、与前后段关系、图表用途和仍缺材料。
保持同一个问题、验证对象和产出边界，不生成插入式申请正文。
把需要申请人补证或确认的内容写成明确任务，而非隐藏占位句。
```

例如，C1 段落的任务是解释：
候选只改变哪一步，哪些条件与对照相同，
用哪个终点区分竞争解释，以及什么结果会削弱机制主张。
不能只列出模型名称、模块和预期性能。

题目与摘要应在论证稳定后整理。
在受限模式下，可以指出题目是否夸大范围、摘要遗漏哪项逻辑，
并给出修改任务；不能以摘要模板为名绕开生成正文的限制。

完整的虚构产物见
[细胞扰动课题的章节任务书](../skills/writing-funding-proposals/examples/section-brief-walkthrough.md)。
它把问题、证据、比较、年度安排与审阅串起来，但不是申请人提交稿。

## 14. 图表：只有帮助判断时才制作

请提供图的论证任务、正文位置、真实数据或方法对象，
以及当前允许的 AI 图形辅助范围。
图示首先服务于一个判断，不按模板凑数量。

贯穿案例可用一个方法比较图说明共享输入、唯一变化的状态匹配步骤、
同信息对照和判断出口。
没有实验结果时，不画带成绩的性能图，也不把计划流程画成已经完成的工作。

```text
先为研究方案制定最小图表任务清单。
说明每张图帮助评审判断什么、放在哪个段落、来自哪些材料。
合并重复用途，区分概念示意与真实数据图。
图形辅助政策未核实时只提供任务书或审阅现有图；
允许制作后再完成可编辑源、所需导出和实际尺寸检查。
```

当前技能的图形路线对政策和保密有单独限制。
允许文字辅助不自动等于允许 AI 图形，私有或受限材料也不能转送外部图像服务。
有关内容见 [图形、审阅与交付](../skills/writing-funding-proposals/references/figures-review-and-delivery.md)。

允许的示意图工作可使用内置
[独立图形路径](../skills/writing-funding-proposals/references/standalone-figures.md)，
不以另装可视化 skill 为前提。
实际宽度由申请表决定，不能照搬期刊栏宽；
真正交付应包含可编辑源和检查过的导出，而不只是生成命令成功。

## 15. 审阅：分别找致命问题、科学问题和阅读问题

请提供同一版本的完整草稿、证据、图表、年度计划和适用要求。
只看某一段可以做局部审阅，但不能据此宣布整份材料已经一致。

```text
使用 $writing-funding-proposals 审阅当前完整材料。
先检查来源、资格证据、本人角色、数据访问、保密与重大矛盾。
再检查中心问题、最近工作、最强替代解释、验证、可行性和年度依赖。
最后检查相邻领域评审能否读懂，核对数字、引用、术语和图文关系。
每条意见给出具体位置、为什么影响判断、最便宜的补证或修改，
并区分已解决、保留有据、仍待确认的问题。
```

三个审阅视角分别对应：

| 视角 | 重点 | 不等于什么 |
|---|---|---|
| 致命问题 | 权威、事实、资格证据、保密、伦理和矛盾 | 用规则通过预测中标 |
| 科学问题 | 问题、差异、对照、可行性、基础、年度与风险 | 更换主张来让稿件好看 |
| 可读性 | 跨领域理解、直接表达、术语、引用与图文一致 | 从标点判断是否由 AI 写作 |

例如，候选提高了分数但同信息对照缺失，应指出机制归因尚不能成立。
没有申请人参与证据，应要求补本人角色材料，不能从作者顺序推断。
意见解决需要真实补证或具体修改，不是给总体评分加分。

内置 prose audit 只能提示可检查的语言表面信号。
它不会替代科学审阅、政策判断或作者责任。
详细表达原则见 [直接中文表达](../skills/writing-funding-proposals/references/plain-chinese-prose.md)。

## 16. 模板整合、真实构建与申请人确认

请提供实际系统模板、申请人确认后的章节与图表、必要附件和机构允许的工具链。
官方指南提到有模板，不等于已取得并检查了当前那个文件。

```text
在已确认的辅助范围内，整合申请人提供的内容与允许使用的图表。
按当前实际模板检查章节、字段、附件、交叉引用与最终版面。
使用项目现有工具真实构建并逐页检查，保留原稿。
输出实际生成的候选文件与仍需申请人确认的事项；本轮不上传或提交。
```

检查应覆盖缺字、截断、重叠、陈旧图件、表格可读性、
引用与正文对应、页数、隐藏批注和未解决占位。
文字数量不能代替实际版面，PDF 文件存在也不能证明构建成功。

交付的应是请求范围内的实际材料。
如果只完成了章节任务书，便称为任务书；
如果渲染工具未运行，便保留可编辑源并说明该步骤未运行。
不能通过填写一个通过状态补出并不存在的完整申请书。

正式上传前，申请人还需确认真实身份、本人贡献、合作、伦理、
数据权限、声明和系统信息。
本地文件完成、平台草稿已保存、已经提交和获得资助是不同事实。

## 17. 只做一个阶段时怎样提问

| 你的当前情况 | 可以直接限定的请求 |
|---|---|
| 只有一个想法 | 只比较科学问题、数据与本人能力，不写正文 |
| 已有数据和论文 | 只找最近工作差异与必要对照 |
| 立项依据冗长 | 只审阅论证链与逐段任务，保留来源范围 |
| 研究内容互相重复 | 只重建科学依赖，说明合并理由 |
| 可行性说得空泛 | 只核对数据、实现、资源与最早失败信号 |
| 前期基础太散 | 只映射真实成果到具体研究任务 |
| 年度计划或预算变更 | 只检查受影响任务、费用与承诺 |
| 申请人已写完草稿 | 按致命、科学与阅读三个视角审阅 |
| 已进入最终准备 | 检查实际模板、构建、页面与申请人确认 |

不用为了一个局部任务从头查遍所有材料。
但如果局部修改改变了数据、终点、科学范围或资源承诺，
应指出它依赖的章节与计划，而不是只修一个段落留下矛盾。

## 附录 A：本地工具与真实科学工作的区别

| 工具 | 实际能力 | 不能据此声称什么 |
|---|---|---|
| `init_proposal_workspace.py` | 建立项目记录与明确未完成项 | 当前政策已核实、方案已成立 |
| `validate_proposal_workspace.py` | 检查记录与本地路径的完整性 | 真实资格、科学正确、文件已渲染或已提交 |
| `audit_chinese_prose.py` | 提示可审阅的表面语言信号 | 作者身份、科学真实性或政策合规 |
| `render_evidence_figure.py` | 按本地规格绘制有来源的小型图形 | 生物学结果或最终申请图质量 |
| `examples/run_demo.py` | 演练合成记录完整性 | 真实申请书或前期基础 |

完整科学与交付路径见
[full-project workflow](../skills/writing-funding-proposals/references/full-project-workflow.md)。
本技能的本地工具不会自行查证全部来源、代替申请人确认或操作申报平台。

以下命令从 `open-research-skills` 仓库根目录执行。
如果之前切换了目录，先回到仓库根目录。
命令使用 macOS/Linux shell，Python 3.9+，只需标准库。

```bash
SKILL_DIR="$PWD/skills/writing-funding-proposals"
DEMO_OUT=$(mktemp -d)
python3 -B "$SKILL_DIR/scripts/init_proposal_workspace.py" "$DEMO_OUT/proposal" \
  --project-id perturbation-proposal --program other --year 2026 --project-type general
python3 -B "$SKILL_DIR/scripts/validate_proposal_workspace.py" "$DEMO_OUT/proposal" \
  --mode working
```

`2026`、`other` 和 `general` 只是可运行的教学参数，不代表实际项目选择。
初始化器拒绝覆盖非空目录。
working 检查允许项目显式保留未知和未完成工作，不代表可以进入正式提交。
上述新建示例预期为 `PASS_WITH_WARNINGS`，并列出政策、论证、预算要求与章节等未完成项。
不要通过填写未经核实的状态来消除这些真实缺口。

对真实项目，final 模式还要求适用来源、真实模板、申请人确认、论证、
条件性预算、承诺、审阅、构建和视觉检查等记录完整。
其报告范围为 `record_completeness`：它不会替你打开政策网页、解析最终 PDF
或判断来源是否真的支持某个主张。
