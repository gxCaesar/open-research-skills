# Survey and planning

Use this reference in `survey` or `plan` mode. The output is a falsifiable research
decision, not a long bibliography or a project calendar detached from evidence.

## Bound the search before opening sources

Define a bounded search budget with explicit query families, source classes, date
coverage, languages when relevant, inclusion criteria, and a stopping rule. Search at
least these axes where applicable:

- scientific claim, endpoint, and alternate terminology;
- task definition, data, split, metric, and strongest representation;
- mechanism, objective, architecture family, and simpler alternatives;
- benchmark, implementation, version, and negative-result reports;
- adjacent fields whose vocabulary differs;
- current venue and article-type precedent.

Keep a failure-mode ledger for directions already checked. Record the query, sources
opened, exact reason each direction failed or remained uncertain, and the evidence that
would reopen it. This prevents the same attractive but unsupported route from returning
under new wording.

Search results locate candidates; only opened primary sources support load-bearing
claims. Use `VERIFIED`, `UNVERIFIED`, `COULD_NOT_OPEN`, and `NOT_FOUND` honestly. An
absence claim requires a dated bounded ledger, not memory or one database.

## Read individual papers as evidence objects

From the installed skill root, use `components/paper-card/guide.md` when one paper needs
deep reconstruction.
Capture source coverage, stable locators, claim-evidence chains, independent units,
splits, comparators, metrics, uncertainty, limitations, and candidate falsifiers. A
paper's own related-work section does not independently establish field novelty.

When a supplied directory or bounded paper set is being used to infer publication,
writing, or figure patterns, read `exemplar-corpus-calibration.md`. Census every input,
separate publication form from scientific contribution, deep-read stratified examples
and counterexamples, and transfer only source-located conditional guidance. Do not treat
observed frequency, editorial quality, and current official policy as the same claim.

## Refresh the current incumbent twice

Identify the current incumbent for the exact task, representation, split, metric, and
information boundary during intake. Repeat the search immediately before protocol
freeze. Record version, implementation source, recipe, reported and reproduced value,
and unmatched differences. A new paper, corrected code path, or stronger simple baseline
can close headroom even when the project hypothesis is unchanged.

## Test execution feasibility before committing

Run a retrainability probe on the strongest required baseline or a representative
public implementation. Establish that data can be obtained and parsed, the environment
can be reconstructed, one small run produces interpretable output, and the evaluation
path reaches the intended unit and metric.

Estimate the cost of one decision-relevant iteration: data preparation, training or
analysis, evaluation, storage, and human inspection. State the minimum useful pilot and
the full frozen run separately. An idle accelerator, runnable demo, or pretrained
checkpoint does not establish retrainability under the claimed protocol.

## Produce a decision-linked plan

The plan must state:

- active authority and exact contribution lane;
- data feasibility, scoop verdict, and venue fit as separate judgments;
- frozen hypothesis, endpoint, direction, minimum relevant effect, uncertainty, and
  independent validation;
- strongest cheap and current field comparators;
- pilot, headroom check, candidate order, final evaluation, and public-release rehearsal;
- finite budget and explicit `advance`, `revise`, `pivot`, and `stop` rules;
- external actions that still require authorization.

Each planned experiment answers a named decision. Remove work that cannot change the
route, protocol, candidate, or claim.
