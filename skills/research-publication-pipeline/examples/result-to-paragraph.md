# From an observed toy result to a bounded paragraph

This page is a curated teaching sample, not a research paper or a completed manuscript.
It explains the arithmetic output actually produced by the
[runnable demonstration](README.md). It deliberately does not reproduce the fixture's
injected scientific claims as if they had been measured.

## Input, operation and observed output

The packaged example reads a JSON array of three synthetic integers. Its `summarize`
function returns the array length and sum:

| Input values | Operation | Observed output |
|---|---|---|
| `[1, 2, 3]` | Count the elements | `count: 3` |
| `[1, 2, 3]` | Sum the values | `total: 6` |

The public-release demonstration writes this small result:

```json
{"count": 3, "total": 6}
```

Its two packaged tests separately check `[4, 5]` → count 2, total 9 and an empty array
→ count 0, total 0. These checks exercise ordinary arithmetic behavior, not a learned
model, a biological endpoint or statistical inference.

## A manuscript-style Results excerpt

The paragraph below is newly written teaching prose about the software demonstration.
It is not a manuscript generated by `run_demo.py`, and it should not be presented as
scientific evidence:

> In the synthetic software example, the packaged program returned a count of 3 and a
> total of 6 for the supplied values [1, 2, 3]. The example and two unit tests executed
> after the code was packaged and unpacked in a fresh temporary directory using the
> existing Python interpreter. This establishes execution of the documented toy case;
> it does not establish a scientific effect or correctness beyond the tested inputs.

Every statement has a narrow support:

| Sentence content | Supporting observation | Boundary |
|---|---|---|
| Count 3 and total 6 | The generated arithmetic result | Applies to the supplied toy input |
| Example and two tests executed | The local packaging rehearsal | Existing interpreter, not a freshly installed environment |
| No scientific-effect claim | No biological or model experiment is run | Do not infer effectiveness from software checks |

This is the basic writing move the skill encourages: retain the quantity's actual
definition and tested population, then state what remains unestablished.

## What would change for a research result

A real result paragraph would need the named dataset and version, data inclusion and
exclusion, independent-unit split, exact comparator, metric implementation and direction,
selection rule, observed per-unit outputs and an appropriate uncertainty analysis.
Repeated seeds are not automatically independent biological specimens.

The demo's `final-comparison.json` contains a synthetic marker, not those observations.
The other example records contain injected numerical claims for validator testing.
Do not lift those values into a paper, calculate a new confidence interval from them,
or describe them as reproduced research.

For an authorized full project, the skill's standalone manuscript route continues
from actual evidence through complete sections, figures, legends, rendering and local
delivery. The simple demo intentionally stops short of those activities. This page
shows a readable output style without pretending the missing scientific work happened.
