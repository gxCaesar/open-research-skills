# 细胞扰动预测：从配对分数到有边界的结论

这个示例教你完成一次很小、但完整的研究分析交付：明确比较对象，读取配对数据，
保留失败任务，写出与结果相称的段落，再把可运行代码交给另一位读者。
它不是状态检查器演示。

## 场景与输入

假设你正在研究：加入扰动前的细胞状态信息，是否能改善未见扰动条件下的响应预测？
在真实项目里，需要先定义细胞背景、扰动身份、预测终点和未见条件，再进行匹配的
训练与评估。本页不假装已经完成这些工作。

[scores.csv](scores.csv) 是六个任务的 **synthetic 合成教学分数**，数值是任意设定的，
并非生物学数据、模型训练输出或真实基准成绩。`task-1` 等标识不代表某个基因、供者或细胞系。
这些数值与仓库中的会议论文教学例子一致，但本目录保存自己的数据副本，运行时不需要其他 skill。

| 字段 | 本例含义 |
|---|---|
| `task` | 唯一任务标签；一行是一组配对分数，不表示独立生物学重复 |
| `baseline` | 基线的任意分数，越高越好 |
| `candidate` | 候选方法在同一任务上的任意分数，越高越好 |

## 1. 运行实际分析

从仓库根目录运行，或把 `SKILL_DIR` 改成完整安装后的绝对路径：

```bash
SKILL_DIR="$PWD/skills/research-publication-pipeline"
DEMO_OUT=$(mktemp -d)
python3 -B "$SKILL_DIR/examples/perturbation-comparison/analyze_scores.py" \
  --scores "$SKILL_DIR/examples/perturbation-comparison/scores.csv" \
  --output "$DEMO_OUT/comparison"
```

需要 Python 3.9+，只用标准库，无需安装依赖、API key、网络或 GPU。
上述 shell 写法适用于 macOS/Linux。`mktemp -d` 创建一个新的父目录；脚本再创建
尚不存在的 `comparison` 子目录。再次运行时使用新的 `DEMO_OUT`，不要覆盖旧结果。

[analyze_scores.py](analyze_scores.py) 读取 CSV，逐行计算 `candidate - baseline`，
按差的符号计数，并对全部任务的差取等权平均。输入必须恰好包含上述三列，任务标签
不可为空或重复，分数与差必须为有限数。平局指原始数值相等，不使用事后容差。
输出中的差与均值最多保留 12 位小数，用于避免展示二进制浮点尾数。
结果说明根据实际正差、负差和平局计数生成；全正或全平输入不会被写成混合方向。

| 输出文件 | 用途 |
|---|---|
| `comparison/differences.csv` | 每个任务的原分数与配对差，可以继续作图或检查失败任务 |
| `comparison/summary.json` | 任务数、正负平局次数和平均差，便于另一个程序读取 |
| `comparison/summary.md` | 实际计算后生成的中文结果说明，也会打印在终端 |

## 2. 先看逐任务结果，再看均值

运行本页随附输入，应得到：

| 任务 | 基线 | 候选 | 候选减基线 |
|---|---:|---:|---:|
| task-1 | 0.62 | 0.64 | +0.02 |
| task-2 | 0.68 | 0.69 | +0.01 |
| task-3 | 0.71 | 0.70 | −0.01 |
| task-4 | 0.66 | 0.68 | +0.02 |
| task-5 | 0.73 | 0.74 | +0.01 |
| task-6 | 0.69 | 0.67 | −0.02 |

`summary.json` 中的核心结果为：

```json
{
  "tasks": 6,
  "wins": 4,
  "losses": 2,
  "ties": 0,
  "mean_difference": 0.005
}
```

完整 JSON 还包含教学数据类型与指标方向。这里的 +0.005 是任意分数单位，不能写成
准确率提升、百分比提升或相对增益。task-3 和 task-6 必须保留在表格和解释中。

## 3. 从结果写出恰当的段落

不成立的表述是：候选方法在所有扰动任务上稳定优于基线。

与本次计算匹配的教学结果段落是：

> 在六个合成教学任务中，候选得分高于基线四次，低于基线两次，没有平局。
> 候选减基线的等权平均差为 +0.005 个任意分数单位。差值方向并不一致，
> 因而这组示例不支持每项任务均改善的表述。

下一步的教学决策是检查负差任务对应的条件和配对关系，而不是删除它们。
若换成真实开发集，应先确认这些条件是否属于预先定义的失败切片，以及两种方法是否
使用相同输入、拆分和评估代码。仅有一个正均值不能决定扩展模型或宣布机制有效。

本例不估计置信区间、不做显著性检验，也不证明新颖性、SOTA、独立重复或生物学泛化。
真实项目需要补齐任务级与供者/批次层级、合适的独立单位、数据许可、训练条件、强基线、
误差尺度和独立验证。这里没有可使用的真实 locked-test，也没有执行训练或实验。

## 4. 做成一个最小可运行源码包

本目录就是源码包的最小起点：分析脚本、合成输入、用法与预期结果均在同一目录，
无需复制整个研究工作区。只复制这个教学目录到新的 `public-release/`，再从包内运行：

```bash
PACKAGE_OUT=$(mktemp -d)
cp -R "$SKILL_DIR/examples/perturbation-comparison" "$PACKAGE_OUT/public-release"
cd "$PACKAGE_OUT/public-release"
python3 -B analyze_scores.py --scores scores.csv --output "$PACKAGE_OUT/recheck"
```

此时输入与代码都来自新副本。检查 `recheck/differences.csv` 的六行和
`recheck/summary.json` 中的 4/2/0、+0.005，再阅读生成段落是否保留负结果。
`recheck` 与代码包分开，不必把本次运行的输出加入源码包。

本示例的原创代码与文档沿用 Open Research Skills 的 Apache-2.0 许可，完整
[LICENSE](LICENSE) 与 [NOTICE](NOTICE) 已随源码放在本目录，再分发时应一同保留；真实研究包还应
补齐可公开数据的获取/预处理步骤、软件版本、对应论文的引用信息及其适用限制。
不要编造尚不存在的论文或 DOI。本页只演练本地复制与执行，不创建远端仓库或上传文件。

## 5. 用到自己的项目中

先让两种方法在相同任务定义和尺度下输出逐任务分数，再使用本脚本做描述性配对汇总。
如果指标越低越好、任务不能等权、存在重复层级或任务尺度不同，应先改清楚分析协议，
再修改脚本与测试；不要只交换列名让候选方法看起来更好。

完整安装的 `research-publication-pipeline` 还提供研究规划与写作指导，其
`examples/run_demo.py` 是记录检查与算术打包的进阶冒烟示例。它不是本分析的前置步骤；
单独复制本目录即可完成这里的分析。
