# Rendered schematic refinement

Use after the first complete, source-faithful schematic is rendered and before delivery.
Apply to standalone diagrams and each schematic panel in a compound or manuscript-wide
figure set. A disposable layout sketch does not need this finish. For measured panels,
refine presentation only: this procedure does not authorize changing data or images.

The goal is a clear, finely composed scientific explanation at manuscript size. Three
passes are the default working budget, not three compulsory redraws or a certificate
of Nature/conference quality. Keep well-resolved elements and improve the weak ones.

## Start from a preserved draft

Keep the initial editable scene and its render as v0. Read the actual figure alongside
its caption and content ledger. Resolve scientific discrepancies from the source before
aesthetic work; keep an unresolved discrepancy visible rather than inventing a repair.
Hold physical width, evidence, notation, comparison scope and semantic colour roles
fixed. Style authority comes from the approved figure family when one exists.

Use the current project renderer and canonical scene. Preserve a version for each
substantive pass, with an actual render, so an attractive but worse revision can be
discarded without losing the last good version. These are working copies, not extra
reviewer-facing deliverables.

## Three focused passes

| Pass | Design work | Compare in the actual render |
|---|---|---|
| 1 — Whole composition | Clarify reading order, grouping, relative area and visual emphasis. Give the core transformation room. Adjust crowded and empty regions using meaningful proximity, alignment and whitespace. | Is the method's distinguishing operation easier to locate? Are the same scientific roles and relationships still visible? |
| 2 — Individual schematic units | Inspect every pictogram, stage, arrow group and legend mark. Refine weak objects and transformations with a consistent vector language. Keep short titles above, the scientific graphic dominant, and necessary symbols or a compact formula below where the layout supports it. | Does each graphic explain its object or operation? Does it remain identifiable at its actual size and fit the surrounding units? |
| 3 — Whole-figure harmonization | Reconcile arrow routes and endpoints, stroke weights, palette, type hierarchy, equation alignment and spacing. Inspect the full composite at final insertion size and in manuscript context when available. | Are labels unobstructed, branches unambiguous, symbols consistent and the full reading path legible without zooming? |

For pass 2, work from the scientific object: a matrix with a meaningful axis change,
a graph transformation, a sequence segment or a compartment can explain more than a
generic module box. Refine its silhouette, relevant internal structure and necessary
state cue; detail earns space only when it adds information. Use schematic marks as
schematics, never as invented measurements, molecular structures or recovered edges.
An abstract operator can remain a clean labelled block when a pictogram adds no meaning.

Cover the label briefly: can a domain reader identify the object or operation? Check
whether its shape implies an unsupported mechanism. Remove decoration that communicates
nothing, but keep the text or symbol needed to disambiguate an abstract concept. Long
equations belong in a separate strip; there is no requirement to place mathematics
under every object. Return each refined unit to the whole figure before accepting it.

## Render, compare and select

For every substantive pass, render the changed scene and compare it side by side with
the last retained version at the same physical width. Inspect the whole figure first,
then any weak local units. Record briefly in the existing author-side QA note:
`version; changed elements; observed improvement or regression; retained version`.
Record the result, not merely the intention to inspect it. No new schema is needed.

Accept a revision when the targeted issue is visibly improved without losing source
fidelity, readable detail, necessary qualification or set-wide consistency. Retain the
previous version if the new one is worse. When the current figure already meets the
task's visual needs, stop early and state why; do not create nominal variants to fill
three slots. After the default passes, continue only for a concrete remaining defect
within scope, not an unspecified promise to make it more beautiful.

Use inexpensive renders between passes. A changed page blueprint still needs its
existing matching layout review; an unchanged one does not need a new layout ritual.
Run the applicable final technical checks on the selected current artifact. A saved
PASS for an earlier file does not cover a later revision. In a figure set, check the
selected versions together so local polishing does not create incompatible styles.

Keep the accepted version, editable source and concise outcome in the handoff. Distinguish
technical checks from visual judgment and report remaining limitations. A successful
refinement does not establish publisher acceptance or authorize manuscript changes,
restricted-image manipulation, installation or publication.
