# Journal showcase: paired units, scoped prose and source data

This is a synthetic teaching excerpt, not an accepted article, biological study or
journal-policy example. It shows what the skill's local reporting checks can verify
and which decisions still require reading the evidence.

Its date identifies the teaching fixture, not a current-policy check.

## Before and after

**Before:** “Twelve independent samples prove that the treatment improves response and
generalizes to the wider population.”

**After:** “Six constructed specimens each contribute one baseline and one follow-up
value. Follow-up exceeds baseline for four specimens and is lower for two.”

There are six specimen rows, not twelve independent specimens. No treatment was
administered; no population was sampled. The paired values are a display exercise.
The revision removes unsupported causal and generalization claims instead of adding
an invented p value or biological explanation.

The [full revised legend](after.md) names the unit, paired measurements, axis meanings,
source file and absence of fitted summaries or tests. The data statement points to the
actual CSV rather than an invented accession.

## Run from an installed copy

Set `SKILL_DIR` to the directory containing the installed `SKILL.md`. Set `DEMO_OUT`
to a fresh directory outside the skill. Python dependencies must already be available.

```bash
DEMO="$SKILL_DIR/examples/showcase"
MPLCONFIGDIR="$DEMO_OUT/.mpl" XDG_CACHE_HOME="$DEMO_OUT/.cache" \
  python3 "$SKILL_DIR/scripts/render_evidence_figure.py" \
  "$DEMO/figure.json" "$DEMO_OUT/figure"

python3 "$SKILL_DIR/components/statistics-reporting/scripts/validate_analysis_register.py" \
  "$DEMO/analysis-missing-unit.json" --mode final --format markdown

python3 "$SKILL_DIR/components/statistics-reporting/scripts/validate_analysis_register.py" \
  "$DEMO/analysis-complete.json" --mode final --format markdown

python3 "$SKILL_DIR/components/data-availability/scripts/validate_data_inventory.py" \
  "$DEMO/data-inventory.json" --mode final --format markdown
```

Run the intentional-failure command separately if the shell stops on nonzero exits.

| Check | Expected observation |
|---|---|
| Plot renderer | Exit 0; `figure.svg`, `figure.pdf`, `figure.png` |
| Incomplete analysis | Exit 1; one `INDEPENDENT_UNIT` error |
| Complete analysis | Exit 0; `PASS`, zero errors/warnings |
| Data inventory | Exit 0; `PASS`, zero errors/warnings |

The two analysis records differ only in whether `independent_unit` is populated.
This isolates the demonstrated validator behavior. It does **not** prove that the
validator detects the incorrect prose, checks raw data counts, selects an appropriate
analysis or verifies repository access. Those tasks require source inspection.

This demo performs no hypothesis test, document rendering, image generation or native
PPTX construction. It illustrates the source-data plot path without replacing the
skill's default concept-to-native-PPTX workflow for schematics.
